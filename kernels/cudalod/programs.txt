# Programs this pipeline compiles and links, one per line.
#
# Two programs, matching upstream (sampling_cuda_nonprogressive.h): the LOD builder and
# the renderer, each linked against lib.cu.
#
# THIS FILE EXISTS BECAUSE MOST OF THE .cu FILES HERE ARE NOT TRANSLATION UNITS.
#
# CudaLOD uses .cu for two different things:
#
#   entry points      kernel.cu, cudalod_render.cu -- compiled and linked
#   include fragments split_countsort_blockwise.h.cu, voxelize_*.cu -- #included into
#                     kernel.cu, and NOT independently compilable
#
# The fragments open a namespace and rely on their includer for lib.h.cu, helper_math.h
# and common.h. Compiling one alone produces spectacular nonsense: the CCCL headers get
# pulled in *inside* the fragment's namespace, and NVRTC reports things like
# "split_countsort_blockwise::cuda::std::__4::__invoke has already been defined".
#
# Naming would not have saved us -- the `.h.cu` suffix hints at "fragment", but
# voxelize_*.cu are fragments with a plain .cu extension. So the link groups are declared
# explicitly here rather than guessed from filenames.
lib.cu kernel.cu
lib.cu cudalod_render.cu
